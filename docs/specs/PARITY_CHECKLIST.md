# RealAmadeus V2 parity checklist (V1 RealAmadeusWeb → Rust V2)

This checklist lists every user-visible feature and behaviour of RealAmadeusWeb V1 that the Rust V2 (Web, Windows, macOS, Linux from one codebase) must reproduce. Each item has an ID, one testable statement, and the spec section that defines it.

**Source of truth.** V1 means the RealAmadeusWeb working tree in `/home/elvelt_admin/Elvelt/dsuv` as the specs read it on 2026-11-16, uncommitted changes included: FreeAPI tries AI Studio first, the global cap is 65000, the mobile quiz/achievement CSS, the V1.4 download links, the `Alt + Enter / F11` docs row, and the Live2D runtime `?v=19`. The specs are the `spec-*.md` files next to this one. A reference such as `spec-lib-core.md §4.2` names the defining section. "Open Qn" is item n of that spec's open-questions list, "App. X" is an appendix, "Rn" is a risk entry, and "Qn" or "Q-xx" is a quirk-register entry.

**How to read an item**

- The default rule is to reproduce V1 exactly, quirks included, unless the item says otherwise.
- `(Quirk)` or `(Quirk, keep)`: odd V1 behaviour that parity keeps.
- `(Decision needed)`: the spec authors consider the V1 behaviour a bug or a product question. The owner must choose keep or fix before the item can be verified.
- `(Decision needed — specs conflict)`: two specs recommend different V2 behaviour (see Gaps §G3).
- `(Fix candidates)`: a fix is recommended and changes nothing visible in the normal path.
- `(V2 addition)`: new behaviour for the V2 release and download flow. V1 does not have it.
- `(Verify)`: platform behaviour to test on the desktop webviews.
- Terms: "desktop" is the Tauri 2 app (WebView2, WKWebView, WebKitGTK). "Web" is amadeus-server plus the WASM frontend. `{base}` is the web mount, `/amadeus`. API paths stay `{base}/app/api/…` (`/amadeus/app/api/…`) as in V1.

## SCR — Screens, flow & layouts (21)

- **SCR-001** `OverlayPanel` has 10 in-memory states (`none, backlog, config, status, changeLog, help, confirmLogout, confirmShutdown, minigame, achievements`); `minigame` is never assigned and `achievements` is set only by the mobile ACHIEVEMENTS button. — _spec-app-part1.md §2_
- **SCR-002** The desktop boot screen (`LoadingPanel`) waits 500 ms, reveals BOOT_LOG line by line (50 ms, or 400 ms for lines containing `...` or blank), animates `[MEM]` from 0 to 32767 over 1500 ms in 30 ms steps, waits 2000 ms, swaps to the `amadeus_logo_v3.png` logo, then finishes after 4000 ms. — _spec-app-part1.md §5_
- **SCR-003** BOOT_LOG text is verbatim (41 lines, in-universe typos such as `Initakising network`, `/sts`, `ROSS:`); `<pos=30%>` is converted to spaces using `measureText("M")` of `18px "DepartureMono", monospace` (fallback 10 px) against a 1920-px line. — _spec-app-part1.md §5_
- **SCR-004** `Config_SkipLoading == 1` finishes the desktop boot via `setTimeout(onFinished, 0)` and the mobile boot synchronously. — _spec-app-part1.md §5, §14.1_
- **SCR-005** The mobile layout is used when `visualViewport.width` (fallback `innerWidth`) ≤ 900, or ≤ 1200 with a coarse primary pointer (inclusive), re-evaluated on window resize, visualViewport resize and `(pointer: coarse)` change, computed before the first render (no flash). — _spec-app-part1.md §11.1_
- **SCR-006** Crossing the mobile/desktop breakpoint swaps the whole tree: ChatPanel state (history, turn count, typewriter, mini game) is lost, while login state, backlog entries, the active overlay and the mobile settings flag survive; switching during boot restarts the boot screen. — _spec-app-part1.md §11.2_
- **SCR-007** Mobile login: no trimming; empty USER ID or PASSWORD → `login_empty`; denied only if the id is not `Salieri` AND the password is not `MakiseKurisu` (`login_access_denied`); success sets user name `Salieri` and goes to boot. — _spec-app-part1.md §13.2_
- **SCR-008** Mobile loading shows the logo and `起動中` (or `Booting` for en) with 1–3 dots cycling every 300 ms and finishes after 1500 ms; it never shows BOOT_LOG. — _spec-app-part1.md §14.1, §14.2_
- **SCR-009** Desktop login accepts when trimmed USER ID and PASSWORD are both non-blank and (id == `Salieri` OR password == `MakiseKurisu`), case-sensitive; success always stores user name `Salieri` and goes to boot; failure shows `ACCESS DENIED` until a later success (no clearing, no timer). — _spec-app-part3.md §2.2_
- **SCR-010** The desktop boot timeline matches: first line at 500 ms, memory animation 4150→5650 ms, `Boot Sequences Start...` at 15500 ms, logo at 17900 ms, chat at 21900 ms (nominal); the `<pre class="boot-text">` is removed when the logo (`.boot-logo`) appears, with no fade. — _spec-app-part3.md §3.3, §3.4_
- **SCR-011** The boot `[OK]` column is `floor(576 / charWidth)` measured at mount (50 with DepartureMono loaded, ≈53/58 with fallback fonts on first boot) — replicate or make deterministic by decision. — _spec-app-part3.md §3.3, Open Q3_
- **SCR-012** The boot sequence runs once uninterrupted (V1's restart-on-parent-rerender quirk is not reproduced). — _spec-app-part3.md §3.5, Open Q4_
- **SCR-013** Shutdown confirm (web) closes overlays/menu, calls `window.close()`, after 100 ms `history.back()` if history > 1, after a further 300 ms navigates to `https://dsuv.elvelt.com/amadeus`; desktop must exit the app instead. — _spec-app-part3.md §11.3, Open Q13_
- **SCR-014** Mobile renders only Login/Loading/Chat, MobileSettings, BackLog and Achievement panels; Status, ChangeLog, Help and Confirmation do not exist on mobile. — _spec-app-part3.md §12_
- **SCR-015** Root state: appState starts `login`; `isTabActive` (menu mode), `menuOpen`, `menuSelectedIndex` (not reset on open/close), `activeOverlay`, `achievementsOpen`, `mobileSettingsOpen`, dimensions, llmStatus (`{"","",-1}`), backlog and confirm message live in the root. — _spec-app-part4.md §7.1_
- **SCR-016** On mount, in both layouts, the root runs `initializeDefaults()`, sets the LLM status (latency −1), preloads Live2D, fires TTS/STT/RAG health checks unconditionally, tracks window resize, and syncs `Config_ScreenMode` on `fullscreenchange`. — _spec-app-part4.md §7.2 (B); spec-app-part1.md §16_
- **SCR-017** Activating menu mode (`isTabActive`) blurs a focused INPUT/TEXTAREA and opens the menu after 450 ms; toggling back within 450 ms never opens it. — _spec-app-part4.md §7.2 (C)_
- **SCR-018** Menu actions: 0 backlog, 1 config, 2 status, 3 toggle screen mode, 4 change log, 5 logout confirm, 6 help, 7 shutdown confirm, 8 close menu; opening an overlay keeps the menu open underneath and returns to it with the same selection. — _spec-app-part4.md §7.3_
- **SCR-019** Screen flow login → boot → chat. Logout confirm returns to login (closes menu and overlays, keeps the backlog, LLM status and menu index) and calls `setUserName("")`, a no-op, so OPERATOR keeps the name until the next login. The menu works in the login and boot states; the MENU button exists only in chat. — _spec-app-part4.md §7.5; spec-app-part3.md §11.3, Open Q6_
- **SCR-020** Shutdown confirm leaves `isTabActive` true (system panel stays zoomed out) before navigating away (QUIRK-7). — _spec-app-part4.md §7.5_
- **SCR-021** On mobile, overlay values without a mobile renderer (config, status, help…) show nothing but still block Tab. — _spec-app-part4.md §7.5_

## API — Server API endpoints & contracts (44)

- **API-001** The client fetches the FreeAPI quota with `GET {base}/app/api/chat/quota` (`cache: no-store`, no body); any network error, non-2xx, bad JSON or non-number `count/max/remaining` yields null and hides the widget. — _spec-app-part1.md §8.1_
- **API-002** The chat API surface is `POST {base}/app/api/chat`, `POST {base}/app/api/chat/stream`, `GET {base}/app/api/chat/quota`, `POST {base}/app/api/chat/vertex-proxy` with `{base}` defaulting to `/amadeus`. — _spec-server-chat.md §1_
- **API-003** POST-only routes answer OPTIONS with 204 + `Allow: OPTIONS, POST` and other methods with 405 (empty body); quota answers HEAD and OPTIONS (`Allow: GET, HEAD, OPTIONS`); a trailing slash gives 308 to the slash-less path; no CORS headers. — _spec-server-chat.md §1.1_
- **API-004** Request bodies are parsed as JSON regardless of `Content-Type` (BOM stripped, ≥16 MB allowed); invalid JSON, non-object or non-array `messages` → 400 `{"error":"Invalid request payload"}`. — _spec-server-chat.md §1.2_
- **API-005** Rate limiter, global counter and chat log are one shared process-wide state across `/chat`, `/chat/stream` and `/chat/quota` (single instance). — _spec-server-chat.md §1.4, Open Q10_
- **API-006** Payload fields `messages, provider, apiKey, model, webSearch, vertexProject, vertexLocation, localProxyHost, localProxyPort, useGCloudCLI, ollamaHost, openaiCompatible, openaiBaseUrl` follow JS coercion rules (`x?.trim() ?? ""`, `!apiKey`, JS truthiness, strict provider equality: `"8"` ≠ 8, missing/null → 0). — _spec-server-chat.md §2.2, §2.4_
- **API-007** Provider routing: 0 OpenAI, 1 Gemini, 2 Claude, 3 Groq, 4 Vertex, 5 Ollama, 6 OpenRouter, 7 local proxy, 8 FreeAPI; any other value → 400 `Unknown provider.` on `/chat` and the non-streaming fallback on `/stream`. — _spec-server-chat.md §2.3_
- **API-008** `/chat` flow: parse → rate limit (provider 8 denied → 200 FREE_FALLBACK_RATE_LIMITED, unlogged; others → 429 with the limiter message) → log `\n[Req #N] Q: …` → dispatch → `sendResponse` logs `[Req #N] A: …`, appends the chat log, returns `{"response"}`; exceptions → provider 8 200 comm-error fallback, else 500 `{"error": message | "Unknown server error"}`. — _spec-server-chat.md §6.1_

## HDR — HTTP caching headers & static serving (8)

- **HDR-001** SSE responses send `Content-Type: text/event-stream; charset=utf-8` and `Connection: keep-alive` (HTTP/1.1 only) and are never compressed or buffered. — _spec-server-chat.md §1.3, Open Q11_
- **HDR-002** Cache policy: every response, API and SSE included, carries `NO_STORE_SET` by default (Cache-Control `no-store, no-cache, must-revalidate, proxy-revalidate, max-age=0`, Pragma `no-cache`, Expires `0`, Surrogate-Control `no-store`, CDN-Cache-Control `no-store`), which overrides handler values (so SSE loses `no-transform` and the quota handler’s `no-store`). — _spec-server-aux.md §7.1, §7.2; spec-server-chat.md §1.3_
- **HDR-003** `/resources` and `/resources/**` (not `/resourcesX`) get `PUBLIC_SET`: Cache-Control `public, max-age=86400, stale-while-revalidate=604800`, Pragma `public`, Expires `86400`, Surrogate-Control `public, max-age=86400`, CDN-Cache-Control `public, max-age=86400`. — _spec-server-aux.md §7.2_
- **HDR-004** 3xx responses get no cache headers; 404s get Cache-Control `private, no-cache, no-store, max-age=0, must-revalidate` (with the path's other four keys, reproducing the mixed `/resources` 404). — _spec-server-aux.md §7.3_
- **HDR-005** (Decision needed) App bundles (V1 no-store) may optionally use `immutable` for content-hashed Trunk assets; `index.html`, manifest, `sw.js` and API stay no-store. — _spec-server-aux.md §7.3, Open Q4_
- **HDR-006** A path ending in `/` (except `/`) gets 308 with `location` minus exactly one slash (query kept) and `Refresh: 0;url=<location>`, empty body, for all methods. — _spec-server-aux.md §7.4_
- **HDR-007** Static files are percent-decoded (spaces, `紅莉栖`), traversal-safe, with Last-Modified/Range/conditional GET; compressible responses are gzip/br compressed, never images or `text/event-stream`; `.wasm` served as `application/wasm`, `.webmanifest` as `application/manifest+json`. — _spec-server-aux.md §7.5_
- **HDR-008** `X-Powered-By`, Next `Vary: rsc…` and RSC payloads are not reproduced; a build ID (epoch ms) is optional. — _spec-server-aux.md §7.6_

   - *Filled from repo:* the root scripts `patch_amadeus.js`, `patch_amadeus2.js` and `patch_amadeus3.js` were never applied to V1, but they define the intended command:
     - `/dev audio input enable` sets the key to `1`, saves, shows the mic button and types 「音声入力を有効化しました。」.
     - `disable` sets `0`, hides the button and types 「音声入力を無効化しました。」.
   - *Decision:* V1 parity means no writer exists (STT-001). Adding the command is a V2 addition.
2. **Desktop shell (window and app lifecycle).** Several specs touch it, but none specifies the window:
   - `spec-app-part4.md`: PlatformShell for fullscreen, save dialog and `app.exit`.
   - `spec-app-part3.md` §11.3: Shut Down exits the app.
   - `spec-css.md` §8.4, §14 and Open Q13: CSP and `minWidth`.
   - `spec-lib-media.md` R2: IPC transport.
   - `spec-pages.md` §7.2: opener plugin.
   - `spec-server-aux.md`: bundled `/resources`.

   *Current skeleton* (`RealAmadeusRust/apps/desktop/tauri.conf.json`):
   - Window: title `Amadeus`, URL `app`, 1280×720, minimum 640×360, resizable, hidden until ready, black background.
   - CSP: allows `raw.githubusercontent.com` (MS Mincho) but **not** `fonts.googleapis.com` or `fonts.gstatic.com`, so the Noto Serif JP `@import` is blocked unless it is vendored or the CSP is extended (CSS-037, PLAT-014).
   - `minWidth` 640 is below the 900 px breakpoint, so narrow windows switch to the mobile layout and reset the chat (SCR-006, PLAT-015).
   - Updater: `tauri.updater.conf.json` points at `…/RealAmadeusRust/releases/latest/download/latest.json`, and its pubkey is still a placeholder.

   *Undecided:*
   - window size versus `Config_Resolution` (`spec-app-part1.md` Open Q);
   - F11 / `Config_ScreenMode` mapped to Tauri window fullscreen;
   - updater UX (the unused key `update_confirm` exists in all 13 locales);
   - save/open dialogs (unused keys `export_title` / `import_title`).
3. **V2 version strings.** The user asked that the Rust edition be "V2" (`spec-app-part3.md` Open Q2, `spec-css.md` Open Q15, `spec-pages.md` Open Q5). Which visible V1 strings change is not specified:
   - Status SYSTEM_VERSION and credits `Real Amadeus v1.4N(Build 20260801_001)`;
   - landing `SYSTEM V1.4 RELEASED` and the message line;
   - V2 entries in the in-app CHANGE LOG (`changelog_v*` keys in 13 locales) and in the site changelog (dictionary `docs.changelog.versions`);
   - docs pages that still describe Unity/Qt.

   *Repo:* `RealAmadeusRust/crates/amadeus-core/src/version.rs` gives `VERSION` (from Cargo), `GENERATION = "V2"` and `display_version()` = `V2.0.0R`. Any new string must fit the 837 px status grid and the 1820 px credits line.
4. **FreeAPI on desktop: relay base URL.** `spec-server-chat.md` Rust mapping B and Open Q1 recommend relaying FreeAPI chat, stream and quota to the official server, but give no URL. *Repo evidence:* the V1 shutdown redirect `https://dsuv.elvelt.com/amadeus` (`spec-app-part3.md` §11.3) and the Tauri `homepage` suggest `https://dsuv.elvelt.com/amadeus/app/api/chat…`. Confirm with the owner. FreeAPI is currently exhausted: the counter file sits at the 65000 cap.
5. **External TTS (:5100), STT (:5101) and RAG (:5102) servers.** These are referenced throughout `spec-server-aux.md` §4–§5, `spec-lib-media.md` §3–§4 and `spec-lib-core.md` §11, but they are not in this repo. Only their HTTP contracts are known, cross-checked against `RealAmadeusQT_clone/src/{ttsservice,sttservice,vectordatabase}.cpp`. The Qt clone also has server-less `NativeTTSService` (QTextToSpeech), `NativeSTTService` (whisper) and `NativeRAGService`. These are not V1 web behaviour; they could become a desktop enhancement but are not parity.
6. **Live2D runtime entry source.** `scripts/cubism-runtime-entry.ts`, which produced `public/resources/live2d/reama-cubism-runtime.js` (uncommitted, `?v=19`), is not in the repo (`spec-live2d-pipeline.md` §0.2). This is closed: the deployed bundle was treated as the source of truth and the three Live2D specs specify it completely.
7. **Migrating web data to the desktop app.** The desktop app has its own localStorage origin and starts empty (`spec-lib-core.md` §13, `spec-i18n.md` risk 5, `spec-app-part4.md` Rust mapping). No spec defines how to carry settings, `RealAmadeus.Memory` or `amadeus_achievements` over. Only conversation export/import exists. *Decision:* accept the empty start, or add an export/import of these keys (V2 addition).
8. **Golden data lives only in the scratchpad.** Several L2D, L2F and JSC items depend on golden data that is not in `RealAmadeusRust` (no `tests/golden` exists yet):
   - `pipeline-probe/trace-A-*.json`
   - `l2d-model-probe/golden/*` (15 files) and `harness.cjs`
   - `render-spec-probe/*`
   - `harness/golden.json`
   - lib-core Appendix G

   Copy them into `RealAmadeusRust/crates/*/tests/golden/` before the scratchpad is cleared. Otherwise those items cannot be tested.

9. **Shortcuts and settings advertised by the docs but not implemented in V1 web.** The docs controls page and the site changelog (`hooks/useTranslation.tsx` lines 181, 236, 501, 556; `spec-pages.md` §3.10) advertise `Alt + Enter / F11` for the screen-mode toggle. V1 web handles only F11 (`RealAmadeusApp.tsx` line 4244), and Alt+Enter behaves as plain Enter. The same Qt changelog entry lists desktop notifications and a lightweight mode, which exist in the V1 web config UI but have no consumer (CFG-009). *Decision for the desktop builds:* add Alt+Enter → toggle screen mode and give these two settings real behaviour (V2 additions), or keep web parity.

### G3. Conflicts between specs (one decision needed before the affected items can be verified)

1. **Web base path.**
   - `spec-server-aux.md` §8.3 and §13: `AMADEUS_BASE_PATH=/amadeus/app`, Trunk `--public-url /amadeus/app/`, origin-absolute `/resources/…`.
   - `spec-pages.md` §0.2/§7.1, `spec-css.md` §5.5/§16 and the skeleton `apps/web/Trunk.toml`: one SPA at `public_url=/amadeus/` (router base `/amadeus`), resources at `/amadeus/resources/…` plus a legacy `/resources/*` alias.

   Affects API-037 and the HDR/CSS items about asset URLs. The API paths are unaffected.
2. **Release tag and asset names.**
   - `spec-server-aux.md` §13: tag `RealAmadeusV2.0`, `RealAmadeus_V2.0R_Win64.msi`, `…_MacUniversal.dmg`, `…_Linux.AppImage`, `…_WebServer_<target>.tar.gz`.
   - `spec-pages.md` §6.1, the skeleton `release/` and `xtask`: `RealAmadeus_V2.0.0R_Windows_x64-setup.exe`, `…_macOS_universal.dmg`, `…_Linux_x86_64.AppImage`, `…_Web_Linux-x64.tar.gz`, `SHA256SUMS.txt`; tag `v2.0.0` or `RealAmadeusV2.0.0` (still open).
3. **Live2D frame loop after an exception.** `spec-live2d-pipeline.md` §7.1 reproduces the stop and logs it. `spec-live2d-framework-render.md` §2.2/R8 catches the error per frame and never stops.
4. **WebGL context loss.** `spec-live2d-pipeline.md` §10.4 and Open Q7 never recover by default; restore is opt-in. `spec-live2d-framework-render.md` R7 says V2 should rebuild on `webglcontextrestored`.
5. **Shader delivery.** `spec-live2d-pipeline.md` §6.2/§6.4 preloads and fetches the 13 shader files, with shader loading as a separate readiness gate. `spec-live2d-framework-render.md` R1/R2 embeds the sources and compiles only 4 programs. Both are pixel-identical, but the preload list and the readiness gate depend on the choice.
6. **Core readiness timeout.** About 10 s in `spec-live2d-pipeline.md` §3.3 versus about 5 s in `spec-live2d-framework-model.md` §3.1.
7. **`<html lang>`.** V1 is static `lang="en"`, which `spec-i18n.md` §3 keeps for parity. The skeleton `apps/web/index.html` uses `lang="ja"`, which `spec-pages.md` §1.2 calls harmless.
