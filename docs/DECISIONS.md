# V2 design decisions (resolving open questions from the porting specs)

The porting specs (`docs/specs/*.md`) describe V1 exactly and list open questions. These are the
binding answers for V2. When a spec disagrees with this file, this file wins.

| # | Topic | Decision |
|---|-------|----------|
| D1 | Web base path | `/amadeus` (Trunk `public_url = "/amadeus/"`). Every page is a SPA route under it: `/amadeus`, `/amadeus/app`, `/amadeus/docs/**`, `/amadeus/download`, `/amadeus/changelog`. API stays at V1 URLs `{base}/app/api/...`. Static files are **base-relative**: V1 `/resources/...` → `{base}/resources/...`, V1 root files (`/amadeus_logo.png`, `/*_STEP*.png`, …) → `{base}/static/...`. Desktop uses base `/`. (server-aux spec proposed `/amadeus/app` + origin-root resources — rejected: one reverse-proxy rule `/amadeus/*` must be enough.) |
| D2 | Release naming | Git tag `v<semver>` (e.g. `v2.0.0`); assets `RealAmadeus_V<semver>R_<Platform>_<arch>.<ext>` (`R` = Rust edition; V1 used `U`/`Q`). |
| D3 | Visible version strings | V2 shows its own version everywhere V1 showed `v1.4N…` (status panel, credits, landing): derive from `amadeus_core::version` (`V2.0.0R`). Change logs keep all V1 entries and gain a V2 entry on top. |
| D4 | Live2D shaders | Embedded with `include_str!` (no runtime fetch). Compile only the programs the model needs (normal/masked/inverted-mask × premultiplied); 5.3 blend/offscreen paths are compiled lazily only if a model uses them. A shader compile failure must not make the model invisible forever: log once and fall back. |
| D5 | Live2D frame loop errors | Catch/contain per-frame errors (log once per distinct message), keep the loop running. |
| D6 | WebGL context loss | Handle `webglcontextlost` (prevent default, stop drawing) and `webglcontextrestored` (rebuild renderer + textures). V1 never recovered. |
| D7 | Cubism Core readiness | Load `live2dcubismcore.min.js` first, then poll until `Live2DCubismCore` answers (the Core's wasm initializes asynchronously); timeout 10 s. Register a real Core log handler exactly once per page (`csmSetLogFunction` may only be called once). |
| D8 | Live2D V1 quirks kept for visual parity | Hair physics runs before the player driver (driver values never reach physics); two Core updates per frame; SDK updaters use `Date.now()` deltas, the player uses `performance.now()` capped at 0.1 s; projection constants (desktop 4.1 / −2.75, portrait 3.3 / −2.1). `destroy()` must release cleanly (V1 threw). |
| D9 | App stylesheet scope | V1 loaded the app CSS only on `/amadeus/app`, and with it the Google Fonts sheet that its first line `@import`ed. V2: `<link id="amadeus-app-css">` and the Google Fonts `<link id="amadeus-google-fonts">` (added by the loader script in `index.html`, inserted disabled off `/app`) are disabled on every route except `/app` (`amadeus_ui::RouteStyles`). A Google sheet that is still loading when `/app` is left stays enabled (its media is still `print`, so it applies nowhere) and is disabled once loaded: WebKit holds back every later stylesheet after a loading link is disabled and enabled again. Landing `<main>` carries class `page-landing`. |
| D10 | `<html>` / `<body>` | `<html lang="en" class="dark">`, `<body class="bg-black text-white min-h-screen selection:bg-purple-500/30 selection:text-white">` (V1 root layout). |
| D11 | Desktop FreeAPI | Relayed to `https://dsuv.elvelt.com/amadeus` (env `AMADEUS_REMOTE_API_BASE` overrides). Desktop has no rate limit / chat log. |
| D12 | Secrets | No hard-coded AI Studio key (V1 had one); env `AI_STUDIO_API_KEY` (fallback `GEMINI_API_KEY`). Service-account JSON only via `AMADEUS_VERTEX_CREDENTIALS`. |
| D13 | Desktop window | min 960×540 (stays above the 900 px mobile breakpoint so resizing never remounts the chat), default 1280×720. CSP must allow Google Fonts (`fonts.googleapis.com`, `fonts.gstatic.com`) like V1 (V1's `raw.githubusercontent.com` MS Mincho download is dropped, see D24). |
| D14 | Mic / STT button | V1 never shows the mic button (the `/dev audio input` patches were never applied). Keep parity: STT service ported, button hidden unless V1's condition enables it. |
| D15 | Settings migration web → desktop | Out of scope for 2.0.0 (users can export/import the conversation from CONFIG). |
| D16 | Vertex JWT lifetime | `exp = iat + 3600` (V1's 3630 s exceeds Google's maximum). |
| D17 | Layout switch remount | Keep V1 behavior (crossing the 900 px breakpoint remounts ChatPanel). |
| D18 | Other V1 quirks | Keep user-visible quirks for parity unless they are crashes, security holes or dead links; fix those and list them in CHANGELOG under "Fixed". |
| D19 | Desktop screen mode (startup, Escape) | The desktop window always starts windowed (window-state never restores fullscreen). `Config_ScreenMode` (0 = fullscreen, 1 = windowed) is synced from the real window state (initial query + `amadeus://fullscreen-changed`), never applied at startup — same as V1 web, where browsers forbid entering fullscreen without a gesture. Escape while the window is in native fullscreen leaves fullscreen like the browser's Escape in V1 (KEY-011, PLAT-001): the platform shell's capture-phase `keydown` listener sends `window_set_fullscreen { fullscreen: false }` and consumes that key press (`preventDefault` + `stopImmediatePropagation`), because browsers never deliver the Escape that exits fullscreen to the page; no overlay, menu or ChatPanel listener sees it (an open achievement panel stays open). The change comes back through `amadeus://fullscreen-changed`, which writes `Config_ScreenMode = 1`. An Escape taken by an IME composition is left alone; windowed, Escape keeps its V1 meaning. The web build is unchanged (the browser does it). |
| D20 | Service quirks kept | Q-A5 (audio `errorOccurred` emitted twice) and Q-C1 (`cancel_streaming` does not abort a non-streaming `send_chat`; `cancel_chat()` exists but is not wired) stay V1-identical. |
| D21 | Desktop STT | The desktop build skips the browser `SpeechRecognition` and always uploads through the backend (PLAT-004). Irrelevant to the UI while the mic button stays hidden (D14). |
| D22 | Core manager singletons | V1's module-level `MemoryManager` / `AchievementManager` / `RandomEventService` / `VectorDatabase` are `amadeus_ui::app::managers` singletons, created by `managers::init()` when the `/app` route mounts (V1 module-evaluation time). `managers::init()` also creates the `services::{ai, audio, stt, tts, rag}` singletons, all in V1's module-evaluation order (spec-lib-core §1.10: memory, achievements, AI, audio, STT, TTS, vector store + RAG client, random events), so constructor effects keep V1's timing and order: `AudioService` reads `Config_VoiceVol` once, at that point (a later change applies after a reload, QUIRK-14), and the STT/TTS/RAG constructor health checks (when enabled) go out before the root's startup checks (CFG-027). Fact ordering uses the browser's `Intl.Collator("ja")` (V1 `localeCompare(…, "ja")`). |
| D23 | Chat streaming (V1 frozen closures) | Adopt spec-app-part2 §6.4 **Option B**: streamed replies leave `waitingAPI` and are typed out (V1 never displayed replies of streaming providers 1/3/4/5/6 — CHAT-028); the typewriter skip keeps typing while the stream is open; the TTS session guard is a real generation counter (TTS-006) and the streamed tail is always flushed (TTS-003); latency uses the live text. Typing and the streamed TTS capture both start only once the leading tag is decided (the same `parsed` gate). **Display:** while a reply streams, what is typed and what the streamed TTS capture receives is always a prefix of the final display that the stream completion produces. Both use only `amadeus_core::chat_utils::stream_display_prefix` of the raw stream, which cleans it in `handleStreamComplete`'s order (memory commands, then `<think>` blocks anywhere, then emotion tags, then trim) and holds back whatever a later token could still change: an unterminated `[SAVE_…` (or a trailing `[`…`[SAVE`), an unclosed `<think>` (or a trailing `<`…`<think`), a trailing `[` that can still become a tag, and trailing whitespace. If the text ever shrinks or changes before the typed part (a `fullResponse` that is not the token concatenation), the page is typed again from its start (the reply from its beginning when earlier text changed). So memory-command text, `<think>` text and half-received tags are never typed or spoken (V1 spoke them, e.g. `[SMIOkay…`), and `[ PANIC ]` is typed as the completion shows it. **Backlog:** each page is logged once, with its final content: pages paused while the stream is open reach the backlog at completion, and a skip during the stream logs nothing. A stream that ends without completing (Ctrl+C / キャンセル, an error, or the chat panel unmounting, e.g. when the layout crosses the 900 px breakpoint) leaves no backlog rows, even for pages already shown. **Cancel (STR-005):** V1's cancel affordances (PC Ctrl+C with the `CTRL+Cでキャンセル` hint, the mobile `キャンセル` button; same element and place as in `waitingAPI`) stay available as long as the stream is open, also while its text is typed (`typing`, `waitForAdvance`; not `inputReady`, which an open stream reaches only through an import). Cancelling aborts the stream and drops the reply, with V1's cancel semantics (no TTS stop); once the stream has completed they disappear. Everything else of §6 stays V1-identical, except the §9 clear of a page whose pause was typed at the end of the text received so far (`\|\| !streamComplete`): that page stays on screen, without its ▼, until more text arrives, which clears it as in V1; if the stream completes without more text the flag is dropped and the end branch keeps the page, so the last ▼ of a streamed reply shows its last page, as after a non-streamed reply (V1's rule would have left an empty box, never visible in V1, which did not display streamed replies). Each page is still logged once. Listed under CHANGELOG "Fixed". |
| D24 | MS Mincho download | V1 fetched `raw.githubusercontent.com/vslabs/winfonts/master/msmincho.ttc`, which is now a dead link (404 + console error on every `/app` load). The CSS already maps "MS Mincho" to `local()` and the bundled Noto Serif CJK, so V2 drops the download (D18 dead link) and the desktop CSP no longer needs `raw.githubusercontent.com` (supersedes that part of D13). |
| D25 | Upstream HTTP client | Every upstream client (chat providers, the Vertex token exchange, the TTS/STT/RAG proxies, the desktop FreeAPI relay, `amadeus-local-proxy`) is built by `amadeus_backend::http::client_builder`: connect timeout 10 s (V1 / undici), read timeout 300 s, no total timeout, at most 20 redirects (the TTS/STT/RAG client also re-checks every hop against `AMADEUS_PROXY_ALLOWLIST`), no `Referer` on redirect hops (V1 parity), `User-Agent: RealAmadeus/<version>` (kept; V1 sent Node's `node`). undici's implicit fetch headers (`cache-control` / `pragma: no-cache` on non-streaming calls, `accept-language: *`, `sec-fetch-mode: cors`) are not sent, and `accept-encoding` offers `br` to every upstream (V1/undici offered `br, gzip, deflate` to `https://` upstreams and `gzip, deflate` to plain-`http://` ones such as Ollama or local TTS/STT/RAG servers); no upstream depends on them (V1_DIFFERENCES 1.20). (API-018) |
| D26 | Page head and preloads | One SPA shell head, the app's (`apps/web/index.html`), on every route: site pages do not get V1's own portfolio head (PAGE-003, V1_DIFFERENCES 8.8). No image preload hints anywhere (no `<link rel="preload" as="image">` tags, no `Link` header; Trunk's own preloads of the WASM module and its JS glue stay): the client-side app boots its WASM before any image is used, so preloads would compete with the WASM download and trigger Chrome's "preloaded but not used" warnings. V1 sent them on `/app` (16) and on some site pages (landing 1, `/docs/login` 1, `/docs/api/openai` 6, `/docs/api/gemini` 5, `/docs/api/claude` 6, `/docs/api/groq` 6, `/docs/api/vertex` 11 plus 6 `<link>` tags) (PAGE-001, V1_DIFFERENCES 8.13). |
| D27 | Server operator configuration | `amadeus-server` binds only via `--bind` / `AMADEUS_BIND`, default `127.0.0.1:9502`: V2 sits behind a reverse proxy, and V1's ports 9501 (production) / 9601 (development) stay free so both can run side by side during the migration; `PORT` / `AMADEUS_HOST` / `AMADEUS_PORT` (proposed by the spec) are not read (API-038). `trunk serve` uses `127.0.0.1:8080` and proxies the API to `:9502`. The FreeAPI global cap is `--free-api-max` / `AMADEUS_FREEAPI_MAX`, default 65000 (V1's `MAX_GLOBAL_REQUESTS`), applied as in V1 to requests for provider 8 or without a provider; it must be a whole number from 1 to 9007199254740991 (blank = the default, anything else stops the server at startup); `/chat/quota` `max`, the 429 message `FreeAPIの全体リクエスト上限（N回）に達しました。…` and the app's FreeAPI quota widget (usage line and exhausted notice) show it, with V1's texts at 65000; the desktop relays FreeAPI and has no limiter (D11) (API-013). A base path that differs from the `<base href>` of `{dist}/index.html` is fatal at startup (error log, exit 1, before the data directory is created or the port is bound); an `index.html` without `<base>`, or none, only warns (API-037). `amadeus-local-proxy` prints its usage for `-h` / `--help` and its version for `-V` / `--version` and exits without listening; other arguments are ignored like V1's `node server.mjs`, and its settings stay environment-only (PLAT-009). |
| D28 | Google Fonts sheet | V1's Noto Serif JP sheet (V1: an `@import` on line 1 of the app CSS) is added by an inline loader script in `apps/web/index.html`, placed between the Tailwind bundle and `amadeus.css` (same cascade and face order), with `media="print"` until it has loaded and `all` afterwards. This fixes V1's blank, unhydrated page while fonts.googleapis.com stalls (D18 *crash* class; the pending `@import` held back the app until the browser gave up on the request): the app starts at once with the bundled faces. It is scoped to `/app` like V1 (D9), so the site pages never contact Google. The desktop CSP allows the loader by its hash (Tauri adds it at build time) and keeps the two Google origins (D13). (CSS-005, CSS-009; V1_DIFFERENCES 12.4) |
| D29 | Tailwind class guard | `cargo xtask check-classes` requires every Tailwind arbitrary-value class (in the utility, a variant or a modifier) found in the string literals of `crates/amadeus-ui/src`, `crates/amadeus-core/src` and `apps/web/src` to exist in the built CSS. Test code is not scanned: the code a `#[cfg(test)]` attribute marks (an item or statement, or only the struct field, enum variant, match arm, argument or parameter it sits on, never the code after it), `#![cfg(test)]` modules, the files of out-of-line test modules (`#[cfg(test)] mod boot_tests;`) and everything below them, `tests.rs` and `tests/`. Where the end of marked code is ambiguous (an or-pattern `\|`, a `>` comparison), the skip stops early, so that test code is scanned (a loud false alarm at worst) and no later code is skipped. `cargo xtask check` runs it after its Trunk build; the CI web job runs it after `cargo xtask dist web`. (PAGE-051) |
